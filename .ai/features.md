# 機能一覧と優先順位

`requirements.md` の機能要件（FR）を、利用者から見える機能にまとめ、作る順を 2 つの段階に分ける。
設計・技術選定・実装方式は扱わない（`architecture.md` と ADR で決める）。

- 段階: 「最初に動かす最小の範囲」と「その後」の 2 つ。どちらも構想の MVP（`brief.md` 6 に挙げたもの以外のすべて）の
  中での作る順で、「その後」に置いた機能も MVP に入る。段階ごとの時期は決めない（`brief.md` 7 の「開発のロードマップ」は未決定）
- 区分: 段階に置いた理由に 1 つだけ付ける。`[explicit]` 構想にある／`[inferred]` 構想から読み取った／`[assumed]` 仮に置いた既定
- 機能要件: 各機能が満たす FR 番号。1 つの FR が段階をまたぐときは、両方の機能に書く（例: FR-032 の週の始まりの設定は F-017）
- 非機能要件（NFR）は機能に分けず、最初に動かす最小の範囲から満たす `[assumed]`

## 最初に動かす最小の範囲

撮って取り込んだお金と、定期項目・単発の予定・カレンダーの予定を、1 つの月表示で見られるところまで。
構想の原則 1（撮影して取り込むだけ）と原則 3（予定とお金を同じ時間軸で見せる）を最初に確かめられる範囲にする。

| ID | 機能 | 理由 | 区分 |
|----|------|------|------|
| F-001 | エントリの土台 | ほかのすべての機能がこのエントリの上に乗る（`brief.md` 4.1） | [inferred] |
| F-002 | 手入力 | OCR を待たずにエントリの記録と表示を確かめられる最短の道で、OCR が読めないときの逃げ道にもなる | [assumed] |
| F-003 | 画像 1 枚の取り込みと確認カード | `brief.md` 5.1 の最重要機能で、原則 1 の中心。1 枚で確認カードまで通れば体験の核を確かめられる | [inferred] |
| F-005 | 画像の保存と削除 | 画像を保存し始める時点から、端末内にだけ置き、消せる手段が要る（NFR-004） | [assumed] |
| F-006 | 月表示 | メイン画面（`brief.md` 5.3）で、原則 3 を見せる場所 | [inferred] |
| F-007 | 日の詳細 | エントリの編集・定期の回のスキップ・その日の追加の入口になる（`brief.md` 5.3） | [inferred] |
| F-009 | 端末カレンダーの予定の読み取り | 原則 3（予定とお金を同じ時間軸）と原則 4（既存のカレンダー環境を尊重）に要る | [inferred] |
| F-012 | 定期項目の登録と各回 | 原則 3 と、コンセプトの「未来のお金」の中心（`brief.md` 1・4.2） | [inferred] |
| F-013 | 定期項目の一覧と管理 | 誤って登録した定期項目を直したり消したりできないと、未来の回が月表示に出続ける | [assumed] |
| F-015 | 単発の予定 | 日付が未来なら予定になる（FR-005）ので、エントリの土台に小さく足すだけで「未来のお金」を入れられる | [assumed] |

## その後

最初の範囲の上に足す機能。どれも MVP に入る。

| ID | 機能 | 理由 | 区分 |
|----|------|------|------|
| F-004 | まとめて取り込み | F-003 の確認カードを順に送る形で足せる。1 枚の取り込みで体験の核は確かめられる | [assumed] |
| F-008 | 月のサマリー | F-006・F-012・F-015 の合計の上に足せる集計で、月表示の合計があれば最初の確認はできる | [assumed] |
| F-010 | 表示するカレンダーの選択 | 最初は許可されたカレンダーをすべて出し、選択はその上に足す | [assumed] |
| F-011 | 標準カレンダーの作成画面を開く | 予定は OS の標準アプリでも作れるので、なくても最初の範囲は使える | [assumed] |
| F-014 | 定期項目の各回の履歴 | 各回は日の詳細（F-007）で見られるので、一覧からの履歴は後に足す | [assumed] |
| F-016 | 予定に金額を添える | F-009 の予定の読み取りと F-015 の単発の予定の上に足す | [assumed] |
| F-017 | 週の始まりの設定 | 最初は日曜始まりで出し、設定は後に足す | [assumed] |
| F-018 | CSV の書き出し | データを端末の外へ持ち出す唯一の手段で MVP には入るが、日々の記録と表示が先に要る | [assumed] |

## どの段階にも置かないもの

| 項目 | 扱い |
|------|------|
| 支払い日が土日祝の場合の調整 | 未決定（`requirements.md` の「未決定事項」）。MVP に入れるかも未決定なので、どちらの段階にも置かない |
| `brief.md` 6 に挙げたもの | MVP に含めない（`requirements.md` の「範囲外」のとおり） |
| 有料の機能 | 無料 / 有料の境界が未決定。この文書の機能は、どれも有料かどうかを前提にしない |
