# MVP の定義（M1）

M1 は MVP（最初に出す版）。`brief.md` と `requirements.md`（FR-001〜FR-038・NFR-001〜NFR-018）から、M1 に入れる
範囲を定める。構想の節との対応は `brief-map.md`。要回答の答えで変わる箇所は「未確定」と書き、どの決定も答えを前提にしない。

## 利用者

- 予定を Google カレンダーなどの端末のカレンダーで管理していて、これからの支払いと収入を予定と一緒に見たい個人。
  カテゴリ分けや予算管理はしたくない人 [inferred]（`requirements.md` の「目的と利用者」）
- 支払いは紙のレシート、QR 決済、ネット通販が混ざる。日本語のレシートと画面、円で使う [inferred]（`brief.md` 5.1・4.1）
- 家族での共有はしない。1 人で使う [explicit]（`brief.md` 6）
- 1 台の端末で使う [inferred]（`brief.md` 6 で端末間の同期を入れないことから）
- iOS と Android の両方 [explicit]（`brief.md` 3）

## 最初に通す一連の流れ

M1 の完了を確かめる流れ。最初から最後までネットワークなしで通す（NFR-002）。

1. アプリを開くと月表示が出る。この時点では権限を求めない [assumed]（NFR-005・NFR-006 の既定）
2. 設定で表示するカレンダーを選ぶ。このとき理由を示してカレンダーの権限を求め、予定が月表示に出る（FR-021・FR-022・NFR-005）
3. 家賃（毎月・支出）と給与（毎月・収入）を定期項目として登録する。未来の回が実績と見分けられる形で月表示に出て、
   月のサマリーに予定支出と予定収入が出る（FR-009・FR-010・FR-032・FR-034）
4. レシートを撮影する。金額・日付・店名が入った確認カードが出て、「保存」の 1 タップで今日の支出合計に入る
   （FR-025〜FR-029）
5. 日付をタップし、その日の予定とエントリを見る。定期項目の回を「この回だけ修正」する（FR-033・FR-012）
6. 手入力で金額だけを入れて支出を足す（FR-031）
7. 日付が過ぎると、予定だった回が確認の操作なしに実績になる（FR-006）
8. 設定からエントリを CSV で書き出す（FR-036）

## M1 に入れる FR

| ID | 理由 |
|---|---|
| FR-001 | すべての記録の土台になる 1 種類のエントリ |
| FR-002 | 金額は必須。合計とサマリーが成り立つ前提（ADR 0001） |
| FR-003 | 支出と収入を分けて表示するのに要る |
| FR-004 | 入力の手間を減らす既定で、作る量が小さい |
| FR-005 | 実績と予定を同じ時間軸で見せる核 |
| FR-006 | 確認作業を増やさない原則の核 |
| FR-007 | CSV の列と表示の区別に要る |
| FR-008 | 分類させない原則。持たないことを M1 から守る |
| FR-009 | 未来のお金を見せるコンセプトの中心 |
| FR-010 | 家賃・給与・ボーナスなど主な支払いの周期を表すのに要る |
| FR-011 | 月末の扱いがないと毎月の回の日付が決まらない |
| FR-012 | 目安の金額を各回で直せないと予定が実際とずれる |
| FR-013 | 請求がなかった回を消せないと合計が狂う |
| FR-014 | テンプレートを変えたときに過去が変わらないことを保証する |
| FR-015 | 削除で過去の実績を失わないため |
| FR-016 | スキップした回を数えないと合計が狂う |
| FR-017 | カードの二重計上を防ぐ短い案内で、作る量が小さい |
| FR-018 | 定期でない未来のお金を入れる最小の手段 |
| FR-019 | 構想が MVP に入れている。予定の選択と紐づけの保存が要り、FR-018 で同じお金は表せるので、後に回す候補（未確定・OQ-002） |
| FR-020 | 単発の予定を使わなくても他が動く前提 |
| FR-021 | 予定とお金を同じカレンダーで見せる核 |
| FR-022 | 見たいカレンダーだけを出すのに要る |
| FR-023 | 予定の作成と編集を OS 標準の画面に任せる（`requirements.md` の「範囲外」）。アプリから作成画面を開く入口は後に回す候補（未確定・OQ-002） |
| FR-024 | ユーザーのカレンダーに書き込まない原則 |
| FR-025 | 記録は撮って取り込むだけ、の最重要機能 |
| FR-026 | 取る項目を合計・日付・店名に絞る |
| FR-027 | 日本語のレシートの読み取りの精度に要る |
| FR-028 | 読み取れなかった項目の扱いを決める |
| FR-029 | 保存の 1 タップで完了する体験の核 |
| FR-030 | まとめて選んだ画像を確認する手段（構想は複数枚の選択を強調している） |
| FR-031 | 撮影できない支払いを補う手段 |
| FR-032 | メイン画面 |
| FR-033 | 日ごとの確認と、各回の修正・スキップの入口 |
| FR-034 | 今月と、この先のお金を一目で見せる |
| FR-035 | 登録した定期項目を直し、終える手段 |
| FR-036 | M1 で唯一のデータの持ち出し手段（無料） |
| FR-037 | 画像を端末の外に出さず、消せるようにする |
| FR-038 | 金額のないカードを保存させない（ADR 0001） |

| ID | 後に回す部分 |
|---|---|
| FR-019 | 予定を選んで金額を付ける機能の全体。未確定（OQ-002） |
| FR-023 | アプリから標準カレンダーの作成画面を開く入口だけ。作成と編集を OS 標準の画面に任せる点は変わらない。未確定（OQ-002） |

## 非機能要件

NFR-001〜NFR-018 は、すべて M1 で守る [assumed]。NFR-012（予定の取得を差し替えられる作り）と
NFR-013（開始残高を後から足せるデータ構造）は、作りの要件として M1 から満たす。

## M1 に入れないもの（FR の外）

`requirements.md` の「範囲外」（`brief.md` 6）は M1 に入れない [explicit]。

## M1 の完了の目安

- M1 に入れる FR のすべてに受け入れ確認があり、自動テストで通る。自動にできないものは理由を書いて手で確かめる [assumed]
- 「最初に通す一連の流れ」が、iOS と Android の両方で、ネットワークなしで最後まで通る（NFR-001・NFR-002）
- OCR の精度を、作った画像か使う許可のある画像のサンプルで計測でき、結果が記録されている（NFR-014・NFR-015）。
  精度の目標の値は M1 の完了の目安に含めない [assumed]
- NFR-009・NFR-010 の時間の目安を計測し、結果が記録されている [assumed]
- ストアへの公開とデプロイは M1 の完了の目安に含めない。完了は「両 OS で公開できる状態」まで [assumed]（公開はマスターが行う）
