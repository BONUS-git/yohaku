# PRO-003 MVP の定義案と MVP にかかわる要回答をまとめる
状態: done

## 目的

目標の条件 2（`.ai/features.md` の最初に動かす最小の範囲）の前提として、M1（= MVP）の範囲を定める。
構想（`.ai/brief.md`）と要件（`.ai/requirements.md` の FR-001〜FR-038）から、M1 に入れる FR と入れない FR を
理由つきで決める。MVP の範囲でマスターにしか決められない点は「要回答」にする。

## 範囲

- `.ai/mvp.md` を新しく書く（利用者・最初に通す一連の流れ・M1 に入れる FR と入れない FR・完了の目安・未確定）
- `.ai/brief-map.md` を新しく書く（`brief.md` の節ごとに、対応する FR・NFR）
- `.ai/open-questions.md` に、MVP の範囲にかかわる要回答（OQ-002〜OQ-004）を足す

範囲外: `.ai/features.md`（この変更では作らない）。`.ai/brief.md`・`.ai/requirements.md`・`.ai/status.md`・
`.ai/README.md`・`scripts/` の変更（マスターの指示で、この変更で触れるのは上の 3 つとこのチケットだけ）。

## 受け入れ確認

- `.ai/mvp.md` に「M1 に入れる FR」と「M1 に入れない FR」の表がある。FR-001〜FR-038 のどれも、どちらか一方の表にちょうど 1 回ずつ出て、各行に一行の理由がある。OQ-002 の答えが出るまでは構想どおり（入れない FR は「なし」）で、後に回す候補は別の表に未確定として書く
- `.ai/mvp.md` に MVP の利用者・最初に通す一連の流れ・M1 の完了の目安がある。構想にない判断には `[assumed]` が付いている
- `.ai/mvp.md` は要回答の答えを前提にしない。答えで変わる箇所は OQ の番号を付けて「未確定」と書いてある
- `.ai/brief-map.md` に `brief.md` の節ごとの FR・NFR の対応がある。FR-001〜FR-038 と NFR-001〜NFR-018 がすべて、どこかの行に出る
- `.ai/open-questions.md` の追加項目は、一覧の表の同じ行に `OQ-NNN` と `要回答` があり、`### OQ-NNN — <題>` の本文に質問と暫定がある
- `.ai/features.md` を作っていない
- `sh scripts/check.sh` が通る

## テスト

新しい検査は足さない。この変更は `.ai/` の中の決められたファイルに限るので、`scripts/` に検査を足せない。
`sh scripts/check.sh`（チケットの 1・2 行目、空の文書がないこと、要件の表）で確かめる。受け入れ確認の残りは、
手順の grep と差分を読んで確かめる。
